# 终于成功了

经过了无数次的 404 和 XML 乱码，我的博客终于上线了。
这是我在边地修行的开始。

前言：为什么要在手机上折腾？
我没有电脑在身边，只有一部手机，装了 Obsidian。
我想建一个独立的博客，拥有自己的数据主权，而不是被困在某些平台的算法里。
作为一个非程序员，我以为只要复制粘贴几个代码就能搞定。结果，我从“Hello World”到真正看到网页，经历了一场长达数天的“认知战”。
如果你也想尝试在 手机 (Android/iOS) + Obsidian + GitHub Pages 的纯移动端环境下部署 Hugo 博客，这篇“血泪史”或许能帮你节省 90% 的时间。
🕳️ 坑一：仓库命名的“隐身术”陷阱
错误操作： 我给 GitHub 仓库起名叫 .github.io。
后果： 网页能打开，但 CSS 样式全丢，页面在“裸奔”。
原因： 在 Linux/Unix 系统中，以 . 开头的文件或文件夹被视为“隐藏/系统文件”。GitHub Pages 默认不会加载这些路径下的资源。我给自家大门上贴了个“隐身符”，结果访客（浏览器）根本找不到门。
修正： 仓库名必须干净，比如 myblog，千万别自作聪明加点。
🕳️ 坑二：Obsidian 的“强迫症”后缀
错误操作： 在 Obsidian 里新建自动化脚本 hugo.yml。
后果： GitHub Actions 死活不运行，构建一直挂起。
原因： Obsidian 是个笔记软件，不是代码编辑器。它会自作主张地给所有新文件加上 .md 后缀。我在文件列表里看着是 hugo.yml，实际上发到云端变成了 hugo.yml.md。GitHub 根本不认识这个戴着面具的文件。
修正：
 * 方案 A： 在手机文件管理器里强行重命名，去掉 .md。
 * 方案 B（最稳）： 先上传到 GitHub，然后用手机浏览器的网页版 GitHub 进行重命名。
🕳️ 坑三：看不见的“地下室” (.github 文件夹)
错误操作： 试图在 Obsidian 里把脚本拖进 .github/workflows 文件夹。
后果： 文件夹创建了，但在 Obsidian 里凭空消失了，怎么也找不到。
原因： Obsidian 强制隐藏所有以 . 开头的系统文件夹，无论你开了多少个“显示所有文件”的开关。我看不到它，自然没法把文件放进去。
修正： “曲线救国法”。先在 Obsidian 根目录建立 ci.yml 并上传，然后去 GitHub 网页端，通过“编辑文件名”的方式，手动加上路径 .github/workflows/hugo.yml，让云端帮我归位。
🕳️ 坑四：精神分裂的文件结构
错误操作： 一会儿把主题文件放在根目录，一会儿又想用 themes/paper 文件夹。
后果： Hugo 彻底懵了，生成的网页全是 XML 代码或者 404。
原因： 手动搭建 Hugo 结构极其容易出错。
修正： “凤凰计划” (Phoenix Protocol)。不要自己造车。直接 Fork 主题作者的仓库（如 hugo-paper），把别人的成品车克隆过来，然后改改车牌（配置文件）就能上路。这是最适合小白的方案。
🕳️ 坑五：GitHub Pages 的“开关”之谜
错误操作： 脚本写好了，但 Pages 设置里还选着 Deploy from a branch。
后果： 网站显示的是我的 README.md 说明书，而不是博客网页。
原因： 我没有把控制权移交给自动化机器人。
修正： 必须去 GitHub Settings -> Pages，把 Source 改为 GitHub Actions。这是点火发射的关键按钮。
🕳️ 坑六：复制粘贴的“脏数据”
错误操作： 从网上复制配置代码时，不小心带上了 `` 这种网页标记。
后果： 整个网站构建崩溃，红色报错。
原因： 配置文件（TOML/YAML）对格式要求极高，多一个空格、多一行乱码都会炸。
修正： 保持配置文件的绝对纯净。看不懂的代码宁可不加，也不要乱加。
🛠️ 最终的成功路径（极简版）
如果你想复刻我的成功，请放弃“从零搭建”，直接走这条路：
 * Fork： 在 GitHub 网页上直接 Fork 一个喜欢的 Hugo 主题（如 hugo-paper）。
 * Clone： 用 Obsidian Git 插件把这个新仓库克隆到手机。
 * Deploy： 在根目录新建自动化脚本（内容找 AI 要标准版），上传到 GitHub。
 * Rename： 在 GitHub 网页端把脚本移动到 .github/workflows/hugo.yml。
 * Switch： 在 GitHub 设置里把 Pages Source 改为 GitHub Actions。
 * Write： 在 content/posts 里写下你的第一篇文章。
结语
技术不应该是阻碍表达的高墙。
即便只有一部手机，即便不懂代码，只要拥有**“遇到报错-分析原因-寻找替代方案”**的逻辑闭环，我们依然可以在数字荒原上建起属于自己的庇护所。
我的博客名为“边地修行录”。这一次搭建过程，本身就是一场修行。
